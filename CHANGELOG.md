# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- Osirion.Blazor.Cms.Web: `TableOfContents` has a `ShowNumbers` parameter, on by default. `ShowNumbers="false"` renders a plain list without the `1.` and `1.2` numbers, which the stylesheet added to every table of contents; the numbering rules now apply only under the `osirion-toc-numbered` class it puts on the `nav`. `DocumentPage` passes it on through `TocShowNumbers`

### Fixed
- Osirion.Blazor.Cms.Domain: `LocalizationOptions.SupportedCultures` (the CMS admin's `Localization` section) from configuration replaces the default instead of adding to it. The list started as `["en-US"]` and configuration binding appends to an existing list, so `["sr-Latn-RS"]` became `en-US`, `sr-Latn-RS`. The list now starts empty and `GetEffectiveSupportedCultures()` gives `["en-US"]` while none is configured; `AddSupportedCultures` and `SetDefaultCulture` still add to `en-US` when nothing was configured
- Repository: a `SECURITY.md` says which versions get security fixes and how to report a vulnerability privately, and private vulnerability reporting is on. The issue form's contact links no longer point at GitHub Discussions, which are not enabled; they lead to the documentation and the private report form. The contact page and the developer notes under `docs/` say the same
- Docs: no heading on getosirion.com starts with a number any more. 111 headings in 15 guides and posts read "1. Install the templates" or "Step 2: Add content to GitHub", which the table of contents, numbering sections itself, showed as "1.1  1. Install the templates"; the text that said "see step 3" now links the section by name. A link from the `OsirionStyles` page to `/docs/security#4-write-a-content-security-policy` pointed at no section, because heading ids never carried the number. Two site tests check every sitemap page: no heading starts with a number, and every link to a section finds it
- Osirion.Blazor.Theming and Osirion.Blazor.Core: `OsirionStyles`, `ThemePicker` and `OsirionHtmlRenderer` link their stylesheets through the component's `Assets`, so apps that use `MapStaticAssets` get fingerprinted addresses that browsers may cache for a year. The plain addresses were cached for four hours and revalidated after that
- Osirion.Blazor.Cms.Web: `SeoMetadataRenderer` no longer writes `dns-prefetch` and `preconnect` hints for the site's own address. The browser is already connected to it, and the `crossorigin` preconnect opened a second connection that nothing used
- Examples: the Bootstrap example site's hero and cover image (`osirion-hero.png`, `blazor-cover.png`) is a 256-color PNG of 29 KB instead of 160 KB, links `blazor.web.js` by its fingerprinted address, and drops the Unsplash preconnect that only a lazy menu image used. Lighthouse mobile on a local build: the home page's largest contentful paint fell from 2.7 s to 2.0 s and a blog post's from 2.8 s to 2.2 s
- Docs: getosirion.com's `/robots.txt` comes from a `robots` content item that names the sitemap and keeps crawlers off `/search`; it served the generator's default rules, which named no sitemap. The packages page at `/docs/packages` declared `/components` as its canonical address, so search engines would have dropped it; its title and description now describe the packages. Tests hold every sitemap page to its own canonical address
- Osirion.Blazor.Cms.Web: content dates follow the language of the content item (its `Locale`: the `lang` front matter, the locale folder or `DefaultLocale`) instead of the server's culture, so an English documentation page on a Serbian Windows server reads "Last updated: October 17, 2026" and no longer "Last updated: oktobar 17, 2026". `DocumentPage`, `ContentView`, `LocalizedContentView`, `ContentPage`, `ArticlePage`, `FeaturedPostsSection` and `OsirionContentListSection` use the item's culture, and the current culture when the locale is missing or not a culture name. The dates are written in `<time datetime="yyyy-MM-dd">` elements, `DocumentPage` gains `LastUpdatedText` for its label, and Osirion.Blazor.Core's `OsirionArticleMetdata` and `HeroSection` gain a `Culture` parameter

### Added
- Osirion.Blazor.Templates: a new template package. `dotnet new install Osirion.Blazor.Templates` then `dotnet new osirion-blog -n MyBlog` creates a Markdown blog on .NET 10 with static server-side rendering: the newest posts on the home page, a blog list, posts, an About page, a 404 page, RSS, Atom and a sitemap, with the menu and footer from `appsettings.json`. `--SiteName` and `--SiteUrl` fill in the name and public address. ### Fixed
- Osirion.Blazor.Core: `OsirionCookieConsent` reopens its category panel for a page opened with `?customize-cookies` after the visitor answered, with their saved choices checked, so a "Cookie settings" link can change or withdraw consent. Before, the banner never rendered again once answered, and consent could only be withdrawn by deleting the cookie
- Osirion.Blazor.Core: the Copy button restores its own accessible name after a copy. Two seconds later the script set a generic "Copy code to clipboard", so "Copy C# code to clipboard" lost its language
- Osirion.Blazor.Theming, Osirion.Blazor.Core: the theme, palette and announcement dismissal cookies are always `Secure`. The flag followed `Request.IsHttps`, so behind a proxy that ends TLS without forwarded headers an HTTPS site set them without it. Browsers treat `localhost` as secure, so local development keeps them. The theme and palette cookies stay readable by script, which applies and replaces them
- Osirion.Blazor.Navigation: `MenuGroup` with `Collapsible` renders its label as the `summary` of a `details` element, so a click, Enter or Space opens and closes the items without script, and `Expanded` sets the starting state. The label was a plain `div` and a rule hid the items of a group with `Expanded="false"`, so they stayed hidden with no control to open them. A collapsible group without a `Label` now stays open
- Osirion.Blazor.Navigation: `Menu.AutoExpandActive` keeps the submenu of the active item open in a vertical menu, as its description says. Only the `osirion-menu-auto-expand` class was written. The rule written for it needed `osirion-menu-item-has-submenu` and `osirion-menu-item-active` on one element, which no markup had (the first is on the wrapper, the second on the link), and the 4.1.0 stylesheet dropped it, so the submenu of the page the reader was on stayed closed
- Osirion.Blazor.Core: `OsirionReadMoreLink` computes its accessible name on every render, `AriaLabel` or else the current `Text`, and draws its focus outline and button ring on `:focus-visible`. `OnInitialized` copied `Text` into the `AriaLabel` parameter once, so after `Text` changed the link still announced the first text, and a mouse click drew the keyboard focus outline
- Osirion.Blazor.Core: `OsirionBreadcrumbs` writes `Style` on its `nav` element. It never wrote it, so `style="..."` in the markup was dropped
- Osirion.Blazor.Core: `OsirionBreadcrumbs` decodes percent-encoded segments for the crumb text and keeps the links encoded, and shows an invalid escape as written. Segments were shown as they sit in the URL, so `/docs/caf%C3%A9` read "Caf%C3%A9"
- Osirion.Blazor.Navigation: `Menu`, `MenuItem`, `MenuGroup`, `MenuDivider`, `MenuCallToAction`, `MenuImageCard`, `MenuPanel` and `MenuPanelLink` write `Style` on their root element. None of them did, so `style="..."` in the markup bound to the parameter and was dropped from the output. `Menu` writes it before the sticky `z-index`
- Osirion.Blazor.Navigation: `Menu` gives the brand logo an empty `alt` beside `BrandText` and `Home` without it, and declares it 36 by 36 pixels, the size the stylesheet draws. The alt text was `<BrandText> brand logo`, so the name was read twice beside visible text and read as " brand logo" without it, and the 60 by 60 attributes disagreed with the 2.25rem the CSS draws
- Osirion.Blazor.Navigation: `MenuImageCard` renders `alt=""` when `ImageAlt` is not set, which marks the image as decorative. It rendered no `alt` attribute, so a screen reader read the file name of the image aloud in front of the caption
- Osirion.Blazor.Theming: `theme-toggle.js` adds `Secure` to the `osirion-preferred-theme` cookie on HTTPS, as `ThemeService` and `theme-picker.js` do. Before, a theme chosen with the toggle was written without `Secure` even on HTTPS
- Osirion.Blazor.Core: `OsirionContentNotFound` renders the suggestion description and the suggestions title only when they have text, and `Create403` leads to `/` instead of a `javascript:history.back()` address. Before, a suggestion without a description rendered an empty `p` and `small`, an empty title an empty `p`, and the 403 button held a script URL. The static `Create...` methods still return an instance that Blazor cannot render; their documentation now says so
- Osirion.Blazor.Core: `OsirionContactForm` submits when `PrivacyPolicyText` is null or empty. Before, the checkbox was left out but the model still required it, so every submission failed validation with no message shown (`AgreeToPrivacyPolicy` is now set to true when no checkbox is rendered)
- Osirion.Blazor.Theming: `ThemeToggle.OnThemeChanged` is raised, with `light` or `dark`, when the toggle runs in an interactive render mode and a callback is set. It was declared and never raised in any mode. Under Static SSR the browser switches the theme and the server is not told, so the callback is still not raised there; listen for the `osirion-theme-update` browser event on `window`
- Osirion.Blazor.Theming: `ThemeToggle` keeps its behavior in `theme-toggle.js` and passes its settings in `data-default-theme` and `data-framework` on the button. It used an inline `onclick` and an inline script, which a Content Security Policy without `'unsafe-inline'` blocks, so the toggle did nothing on such a site
- Osirion.Blazor.Theming: `OsirionStyles` replaces every `<` in `CustomVariables` and in the configured `ThemingOptions.CustomVariables` with the CSS escape `\3C ` before it writes them into a `<style>` element. They were written as markup, so a value containing `</style><script>` ended the element and put a script into the page
- Osirion.Blazor.Theming: `ThemeService` reads and writes `inverted` in the `osirion-preferred-theme` cookie. It parsed only `light`, `dark` and `system`, and wrote no cookie for `ThemeMode.Inverted`, so an inverted choice was lost on the next request and `CurrentMode` fell back to the default mode
- Osirion.Blazor.Theming: in the dark theme a content category badge draws `--osirion-color-primary-700` on `--osirion-color-primary-200`, the pair the active navigation item uses and the adapter contrast tests hold. It drew primary-600, 3.74:1 under the Bootstrap adapter with Bootstrap's own colors and below 4.5:1 under the MudBlazor and Fluent UI adapters too

Their `.osirion-content-body a` rules never reached the rendered body, which carries no scope attribute, and only painted the badges in the link color: 4.37:1 in the light theme
- Osirion.Blazor.Core: the `OsirionReadMoreLink` `Button` variant keeps its text in `--osirion-action-primary-text` under a dark system preference. The dark scheme's link color rule came later at the same specificity and recolored the text on the fill: #9090d6 on #5c5cb0, 1.97:1

- Osirion.Blazor.Cms.Web: the `TagCloud` count keeps the tag's text color. It was faded to 75% opacity, 3.66:1 on the tag background
- Osirion.Blazor.Core: the `OsirionHtmlRenderer` text link rules leave the links inside an embedded demo alone, so a demo looks as the component does on a page of its own. Before, the renderer's tinted link background sat under each component's own link color: the `OsirionContentNotFound` suggestions on its centered panel read 4.35:1 in the light theme
- Osirion.Blazor.Core: `OsirionContentDemo` loads the copy script for its Copy button, so the button works when the component is used directly on a page. Before it rendered the button with an inline handler and no script, so outside `OsirionHtmlRenderer` a click did nothing
- Osirion.Blazor.Core: `OsirionArticleMetdata` writes `Class`, `Style`, `Theme` and unmatched attributes on its root element, and the author icon takes the stylesheet's `osirion-article-metadata-icon` class (the old `osirion-article-meta-icon` stays). Before, the root always rendered as `<div class="osirion-article-metadata">`, and the author icon alone missed the no-shrink and 70% opacity rules the date and clock icons got
- Osirion.Blazor.Core: the code block header and Copy button in rendered Markdown and `OsirionHtmlRenderer` take the code block's own colors (`--osirion-code-background` and `--osirion-code-text`, with a dark fallback that matches the Okaidia theme). Before, the button's `#f8f8f2` text sat on `--osirion-syntax-background-color`, which only the palettes define, so it read 1.06:1 on white in the light theme and light text sat on a light header under the light palettes
- Osirion.Blazor.Core: `OsirionReveal` hides its content only once the script has armed it (class `osirion-reveal-armed`), so it is visible and in place with script blocked or failing, with `Animate` off and under reduced motion. Before, content started at `opacity: 0` and stayed invisible without the script, and `Down`, `Left` and `Right` kept a 1.25rem offset with `!important` whenever the script did not reveal them
- Osirion.Blazor.Analytics: `GA4Options.DebugMode` writes `debug_mode: true` in the `gtag('config')` call and the script no longer writes `gtag('require', 'linkid')`, whose option `GA4Options.LinkAttribution` is now `[Obsolete]`. The script set `window.ga_debug`, an analytics.js mechanism, so DebugView showed nothing, and `require` is not a gtag.js command (the gtag.js reference lists config, get, set, event and consent)
- Osirion.Blazor.Analytics: the Yandex Metrica tracker writes no `noscript` pixel and the page view module is loaded from `/_content/Osirion.Blazor.Analytics/js/osirion-analytics.js`. The tracker sits in the head, where the `noscript` with a `div` and an `img` is invalid and ends the head for a parser, and the relative `src` asked a page at `/blog/post` for `/blog/_content/...`, a 404, unless the document had `<base href="/">`
- Osirion.Blazor.Analytics: `YandexMetricaOptions.HashTracking` writes `trackHash: true` while `TrackHash` is not set, `ClarityOptions.TrackUserAttributes` and `MatomoOptions.TrackDownloads` are `[Obsolete]`, and the XML docs of `AutoTrackPageViews` and `SiteId` say which providers ignore them. The three options were bound and never read, so a `HashTracking: true` configuration sent no `trackHash`. Clarity has no install-time user attribute setting (only `clarity("identify")` and `clarity("set")` calls) and Matomo tracks downloads with outlinks under `enableLinkTracking`, so those two have nothing to map to
- Osirion.Blazor.Cms.Web: `SeoMetadataRenderer` writes `ai-content-declaration`, `ai-content-detection` and `ai-content-attribution` only from front matter `meta_tags` or the new `SeoMetadataOptions.AdditionalMetaTags`, `DefaultImageWidth` and `DefaultImageHeight` are nullable so an explicit `1200` or `630` stands over the configured size, and a page value of `false` for `EmitMobileMetaTags` or `EnableGeneratedFaq` wins over the options. Every page said `human-created`, the two sizes were read as "not set" and replaced by the configured ones, and the options were combined with `|=` so a page could not switch either off. The `SeoMetadataOptions.SiteDescription` doc no longer claims it feeds the organization schema; nothing reads it there
- Osirion.Blazor.Cms.Web: `SeoMetadataRenderer` uses the front matter `seo_properties.image` as the default social image (after `og_image_url`, before the featured image), `lang` for `og:locale` and `meta_tags` as `meta` elements. Names must be a letter followed by letters, digits and `- _ . :` and not one the renderer writes itself, and values are HTML encoded. All three were parsed and never read, so a page that set `image` shared its featured image and `meta_tags` wrote nothing
- Osirion.Blazor.Cms.Domain: `SeoMetadata.Robots` and `OgType` are empty by default, and `SeoMetadataRenderer` reads the front matter `type` ignoring case. Both defaults were non-empty (`index, follow` and `article`), so an item with front matter never got the renderer's robots value with `max-snippet:-1, max-image-preview:large, max-video-preview:-1` or a computed `og:type` (a ProfilePage said `article`), and `type: techarticle` became a `WebPage`
- Osirion.Blazor.Cms.Web: the item list of a collection page and the blog posting of each listed item join the host and the item URL with exactly one slash. An item URL stored without a leading slash was appended as it was, so the item list of `/docs` held `https://example.comdocs/install`
- Osirion.Blazor.Core: `OsirionTestimonialCarousel` keeps its moving track out of the page width. The stage hid the track with `clip-path` alone, which still counts as scrollable overflow, so every page with the carousel scrolled sideways: 2,216 pixels on a 375 pixel screen and about 1,650 at 1280
- Osirion.Blazor.Cms.Web: the `DocumentPage` title wraps a word longer than the line. A component name used as the title, such as `OsirionResponsiveShowcaseSection`, pushed a 375 pixel screen 41 pixels sideways
- Osirion.Blazor.Core: `OsirionPageLoading` stops its spinner under `prefers-reduced-motion: reduce`. It turned continuously for visitors who ask for less motion
- Osirion.Blazor.Core: `OsirionBackgroundPattern` paints the `TechWave` and `Circuit` patterns, uses one `osirion-bg-image-mask` gradient in both `mask-image` declarations, and `AnimatedGrid` and `TechWave` stop under `prefers-reduced-motion`. The two patterns wrapped a color token in `rgba()`, which is invalid, so the browser dropped the background; the `-webkit-` mask listed its stops out of order (52% then 44%); and the animations ran for visitors who ask for less motion
- Osirion.Blazor.Core: `OsirionFooter` renders no top row when its only content is social links and `ShowSocialLinks` is `false`, and the default copyright link to an external `CompanyUrl` carries `rel="noopener noreferrer"` with its `target="_blank"`. The switched-off links still counted as content, which left an empty `osirion-footer-main` row, and the new tab got `window.opener`
- Osirion.Blazor.Core: `OsirionStickySidebar` writes `TopOffset` to the `aside` as `--osirion-header-height` when it differs from the default of 40. The component built the declaration but never rendered it, so `TopOffset="64"` left the sidebar sticking at 2.5rem. At the default nothing is written, so a site that sets the custom property in CSS keeps working
- Osirion.Blazor.Core: `OsirionContactInfoSection` writes `Class` once on its root element. The markup appended it again after `CombineCssClasses` had, so `class="osirion-contact-info-section extra extra"`
- Osirion.Blazor.Core: `OsirionMetricGrid` applies `Class` and `Style` to its list, gives the `ul` `role="list"` as `OsirionPricingTable` does, and makes each card fill its cell with its own CSS instead of passing the Bootstrap-only class `h-100`. `Class` and `Style` were ignored, the list lost its list semantics where a browser drops them for `list-style: none`, and the cards depended on a framework class
- Osirion.Blazor.Core: `OsirionContextCardGrid` takes its heading and description colors from the theme text tokens, gives each grid its own generated `HeadingId` (an explicit value still works), and renders no empty `h2`, nor an `aria-labelledby` pointing at one, when `Title` is empty. The heading used a fixed `#123b2b` that reads 1.61:1 on the dark theme, two grids on a page repeated the same heading id, and an empty title left an empty heading that labelled the section
- Osirion.Blazor.Cms.Web: the stylesheets of `ContentView`, `LocalizedContentView` and `ContentRenderer` no longer carry about 40 rules for the body's headings, paragraphs, lists, tables, code and links, which never matched; `ContentView` and `LocalizedContentView` keep two, `img` at most as wide as the body and `pre` scrolling sideways, through `::deep`. Scoped CSS compiled `.osirion-content-body p` to `p[b-...]`, and the body's elements carry no scope attribute, so nothing applied (`<div class="osirion-content-body" b-32gl18udl4><h2>Setup</h2><p>Text</p>`). `ContentRenderer` gets its typography from the unscoped `osirion-html-renderer.css` that `OsirionHtmlRenderer` links; the two views write the body outside it and keep the style of your CSS, so no body changes except that a wide image or code block now stays inside its column

### Security
- Osirion.Blazor.Cms.Admin: every routed admin page (`/osirion`, `/osirion/dashboard`, `/osirion/content`, `/osirion/content/edit`, `/osirion/settings`, `/osirion/login`) requires the authorization policy `"Osirion.Cms.Admin"` (`CmsAdminAuthorization.PolicyName`).
